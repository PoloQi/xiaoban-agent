# 本地MySQL开发规范

## 1. 目的与边界

本文件规定“小伴”项目专用MySQL 8.4 LTS实例的安装、启停、权限、秘密和验证方式。

该实例只用于本地开发和合成测试数据，不用于生产，不随Windows自动启动，不替代或升级本机现有的MySQL 8.0.40服务。任何删除数据目录、重置实例或升级MySQL版本的操作都必须单独确认。

## 2. 已确认基线

| 项目 | 基线 |
|---|---|
| 版本 | MySQL Community Server 8.4.11 LTS |
| 来源 | MySQL官方Windows ZIP与官方CDN |
| 地址 | `127.0.0.1:3307` |
| 引擎 | InnoDB |
| 字符集/排序规则 | `utf8mb4` / `utf8mb4_0900_ai_ci` |
| 会话时区 | `+00:00` |
| SQL模式 | `STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION` |
| 开发库 | `xiaoban_dev` |
| 测试库 | `xiaoban_test` |

安全基线同时关闭`local_infile`和二进制日志、禁用文件导入导出目录、关闭X Plugin、启用`skip_name_resolve`，并将最大连接数限制为30。

## 3. 目录与版本控制

所有运行态文件都在项目根目录的`.local/`下，并由`.gitignore`整体排除：

| 路径 | 用途 |
|---|---|
| `.local/mysql-8.4/` | 8.4.11运行时 |
| `.local/mysql-data/` | 独立数据目录 |
| `.local/mysql-logs/` | 错误和进程日志 |
| `.local/mysql-run/` | PID等运行文件 |
| `.local/mysql-secrets/` | 本地客户端选项和后端环境文件 |
| `.local/mysql-8.4.ini` | 项目专用服务端配置 |

不得提交、复制到开发日志或在聊天中展示`.local/mysql-secrets/`内的任何内容。该目录关闭继承权限，只授权创建实例的当前Windows用户。

## 4. 标准命令

首次安装前必须确认官方版本、目标目录、端口和现有实例边界。确认后在项目根目录运行：

```powershell
pnpm db:install
```

脚本会下载锁定版本、比较官网MD5、计算SHA-256、解压、初始化独立数据目录、生成随机凭据、建立空库与分权账号，并执行基线验证。若运行时、数据目录或秘密目录已经存在，脚本会拒绝覆盖。

日常操作：

```powershell
pnpm db:start
pnpm db:verify
pnpm db:stop
```

`db:start`遇到3307被其他进程占用时必须失败；不得终止未知进程。`db:stop`只使用项目本地root客户端选项关闭已识别实例。开发完成后是否保持运行由当前任务决定；本次基线验证后实例保持运行。

## 5. 账号与权限

| 账号 | 数据库 | 权限 |
|---|---|---|
| `xiaoban_migrator` | `xiaoban_dev`、`xiaoban_test` | 仅两个项目库的迁移权限 |
| `xiaoban_app` | `xiaoban_dev` | `SELECT`、`INSERT`、`UPDATE`、`DELETE` |
| `xiaoban_test` | `xiaoban_test` | `SELECT`、`INSERT`、`UPDATE`、`DELETE` |
| `root` | 本机维护 | 仅由本地维护脚本使用 |

应用和测试账号不能建库或改表。后续API只加载应用账号，迁移命令才加载迁移账号；前端不得接收任何数据库变量。

`.local/mysql-secrets/database.env`是后端的本地秘密来源。当前API开发、迁移、合成种子和集成测试脚本只在各自进程内加载该文件；Web进程不接收数据库变量。不得复制到仓库内的`.env`或命令行参数。

## 6. 验证标准

`pnpm db:verify`必须验证并只输出非秘密信息：

- 版本为8.4.x LTS，端口为3307且只绑定`127.0.0.1`；
- 默认引擎、字符集、排序规则、UTC和严格模式符合基线；
- `local_infile=0`、`secure_file_priv=NULL`、`log_bin=0`；
- 开发库与测试库存在；业务表必须来自评审过的迁移；
- 三个项目账号只来自`127.0.0.1`，权限与上表一致；
- 三个账号均可连接各自允许的数据库。

每次升级配置、驱动或迁移框架后都要重新执行该验证。阶段1接入数据库后，还必须执行项目级`pnpm check`和连接失败集成测试。

## 7. 故障处理

- 3307被占用：停止操作并识别占用者，不自动终止进程或改端口；
- 启动超时：查看`.local/mysql-logs/error.log`，日志中不得粘贴凭据；
- 凭据或客户端选项缺失：停止操作，不尝试现有3306账号；
- 数据目录异常：不得自动删除或重新初始化，先记录错误并请求确认；
- 版本升级：新增ADR或更新ADR-002，重新确认官方下载来源和校验值，再建立可回退方案；
- 现有3306异常：视为项目外实例，不用本项目脚本修复或停止。
