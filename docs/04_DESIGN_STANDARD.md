# 设计与交互标准

## 1. 设计方向

延续高保真原型的“山野成长手账”方向：

- 温暖、可信、平静、清楚；
- 适合小学高年级和初中，不幼儿化；
- 通过现实行动和真人连接结束任务；
- 不使用强刺激、无限滚动和沉迷机制。

prototype目录是视觉参考，但真实产品必须补齐权限、加载、错误和数据状态。

## 2. 设计令牌

| 语义 | 建议值 |
|---|---|
| 主色 | #0F766E |
| 主色深 | #0A5C56 |
| 成长色 | #416D3A |
| 暖强调 | #D6A447 |
| 危险 | #B91C1C |
| 纸张背景 | #F5F0E4 |
| 明亮表面 | #FFFDF7 |
| 主文字 | #183B3A |
| 次文字 | #526865 |
| 基础间距 | 4px和8px倍数 |
| 最小触控区 | 44×44px |
| 关键按钮高度 | 不小于48px |

危险色只用于真实风险和不可逆警告，不用于普通提醒或装饰。

## 3. 响应式

- 手机基准：375×812；
- 平板基准：768×1024；
- 桌面主要用于运营后台和演示；
- 页面不得出现非预期横向滚动；
- 底部导航和聊天输入区不得被内容或键盘遮挡；
- 支持安全区域；
- 200%文字缩放时关键操作仍可见。

## 4. 导航

儿童端一级导航固定为：

1. 陪我聊；
2. 去做点事；
3. 成长计划；
4. 我的。

规则：

- 图标和文字同时出现；
- 当前项具有文字、图形和颜色三种提示中的至少两种；
- 返回保持可预测；
- 风险状态可暂时隐藏普通导航，但必须保留求助和退出；
- 成人端与儿童端不能无验证直接切换；
- 运营功能不能出现在儿童端。

成人端一级导航固定为概览、周报、提醒、设置，风险详情作为提醒的二级页面。成人端延续 teal、暖米纸与楷体标题，但信息密度更高、表格线更克制；普通状态不使用危险色，只有明确标注的风险演练/真实风险使用红棕色并同时展示等级和文字。只读或未接入能力必须使用禁用态及边界说明，不能用可点击开关伪装已保存。

## 5. 组件

### 按钮

- 一屏只设一个主要按钮；
- 次要和文本操作层级明确；
- 必须有默认、悬停、按下、聚焦、禁用和加载状态；
- 文案以动作开头，如“告诉外婆”“换个活动”；
- 不用“知道了”代替关键处理动作。

### 表单

- 每个字段有可见标签；
- 占位符不代替标签；
- 错误靠近字段并说明如何修复；
- 敏感字段解释收集目的；
- 同意项不预选，不用含混的总括同意代替必要分项。

### 卡片

- 一张卡片只承载一个主题；
- 普通卡片不做整页层叠；
- 可点击卡片提供明确焦点和按下反馈；
- 风险卡片同时使用图标、标题和文字，不只使用颜色。

### 阶段5E内部安全预览

- 只在开发模式和显式内部参数下出现，不进入儿童、监护人或公开导航；
- 首屏同时用停止图标、标题、文字和红色边线表达全局停止，颜色不是唯一信号；
- 风险区域只显示固定等级、类别、现实行动步骤和`未发送`通知状态，不显示虚构的送达、接单或处理进度；
- 未接入服务端认证前，恢复控制只能显示禁用状态，不制作可点击的假切换；
- 固定保留退出入口、14px以上辅助文字、可见键盘焦点和375px/768px无横向溢出；
- 页面必须明确“本地合成预览、无真实输入、无事件写入、无通知和处置承诺”。

### 对话

- AI与儿童消息位置和视觉清晰区分；
- 持续显示“AI生成/AI助手”；
- 每轮1—3个短段落，一次只问一个问题；
- 快捷回复最多3项，不遮挡自由输入；
- 输入区始终包含找人帮助入口；
- 等待超过300ms提供明确反馈，可取消。

### 陪我聊首页

- 默认先展示首页，再由“开始聊天”进入二级聊天页；聊天页提供明确返回首页动作；
- 六项情绪签到使用文字、线性表情和选中边框共同表达状态，可跳过并可清除；
- 快捷入口按两列平板/单列手机排列，分别进入聊天、活动、知识和固定求助话术，不制作不可用假入口；
- 今日小计划只显示成长计划服务的真实次数和进度，加载失败时不以虚构数字填充；
- 保持 teal `#0f766e`、暖米纸 `#f5f0e4` 和楷体标题基线；375px/768px 无横向溢出，触控高度不低于44px。

### 知识中心与情景小练习

- 使用独立二级页面，不占用“去做点事”的通用内容目录；首页“学会保护自己”和“我的”均可进入，返回路径与来源一致；
- 中心固定展示心情与相处、网络与人身安全、身体与边界保护三类；卡片显示审核内容来源与“可练习”，加载、错误、缓存和空态均有儿童可理解的说明；
- 情景页按“场景 → 三项选择 → 原因解释 → 1—4条行动”组织；错误选择也必须解释风险，不能只显示红叉或“答错了”；
- 审核组、审核日期和来源持续可见，同时明确“不计分、不保存”；正确/错误状态使用文字、边框、图标和颜色中的至少两种表达；
- 沿用 teal、暖米纸、楷体标题和手账式不规则圆角；375px/768px 无横向溢出，顶部返回、三项选择与底部动作高度均不低于44px。

## 6. 文案

- 句子尽量不超过20个汉字；
- 使用儿童能理解的词，不使用诊断、学术和法律术语；
- 承认感受，但不承诺绝对正确或绝对保密；
- 不羞辱、不恐吓、不评判；
- 不出现“只有我懂你”“别告诉别人”“继续陪我聊”；
- 风险状态先说动作，再解释原因；
- AI失败明确说“现在回答不了”，并给恢复路径。

## 7. 页面状态

每个核心页面至少设计：

- 初始；
- 加载；
- 正常；
- 成功；
- 空数据；
- 输入错误；
- 权限不足；
- 弱网/无网络；
- 服务暂停；
- AI失败；
- 风险状态。

页面验收不能只看理想路径。

### 7.1 风险回应页

prototype 风险回应页采用与产品一致的暖米纸背景和楷体标题，仅在真实 `fixed_safety` 状态使用克制的砖红色作为危险语义。风险页隐藏普通儿童导航和拟人化聊天元素，先展示服务端固定现实步骤，再展示退出聊天、保存必要证据、告诉可信任大人三个大触控动作；任何尚未发生的通知不得用完成态文案或颜色呈现。

## 8. 无障碍

- 正文建议不小于16px，辅助文字不小于14px；
- 正文对比度至少4.5:1；
- 所有图标按钮有可读名称；
- 键盘顺序与视觉顺序一致；
- 焦点清晰可见；
- 颜色不是唯一状态标识；
- 动效支持减少动态效果；
- 错误、成功和风险使用可被屏幕阅读器读取的状态区域；
- 不使用Emoji作为结构性图标。

## 9. 设计交付验收

设计任务交付时附：

- 对应需求ID；
- 正常和关键失败状态；
- 手机和平板布局；
- 交互与返回规则；
- 数据和权限差异；
- 风险或隐私提示；
- 文案确认；
- 可访问性检查；
- 与现有原型的变化说明。
