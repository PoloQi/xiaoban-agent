# 阶段2：邀请、角色与同意实现标准

## 1. 状态与范围

状态：已完成（2026-08-17）

本阶段只建立以下合成数据闭环：

`受控站点邀请 → 监护人主动同意 → 儿童化名账号 → 强制未成年人模式 → 监护人撤回 → 儿童功能立即停用`

本阶段不接入真实身份核验、真实联系方式、真实通知、大模型或自由聊天。公开开发邀请码和页面内所有名称均为虚构数据。

## 2. 产品与安全规则

- 邀请必须属于启用站点、处于有效期且未被使用；
- 监护同意不得预选，必须匹配`guardian-consent-2026-08-v1`；
- 儿童必须看到AI身份、普通聊天隐私和真人求助边界，并主动确认`child-boundaries-2026-08-v1`；
- 账号只采集化名和年龄段，不采集姓名、身份证、照片、人脸、手机号、住址或学校；
- 未成年人模式由服务端强制为`true`，儿童不能关闭；
- 监护会话和儿童会话角色严格分离；
- 监护端默认不提供完整普通聊天读取能力；
- 撤回同意后儿童账号和儿童会话在同一事务内停用；
- 邀请码和会话令牌在数据库内只保存SHA-256摘要；
- 关键状态变化写入不可由前端伪造的审计动作。

## 3. 接口与权限

| 接口 | 角色 | 用途 | 幂等 |
|---|---|---|---|
| `POST /api/v1/enrollments/preview` | 未登录 | 核对邀请并读取同意摘要 | 不适用 |
| `POST /api/v1/enrollments/guardian-confirmation` | 未登录+有效邀请 | 记录监护同意并建立监护会话 | `requestId` |
| `POST /api/v1/enrollments/child-activation` | 监护人 | 创建化名儿童并建立儿童会话 | `requestId` |
| `GET /api/v1/guardian/enrollment` | 监护人 | 读取监护同意与儿童状态 | 不适用 |
| `POST /api/v1/guardian/consent/withdrawal` | 监护人 | 撤回同意并立即停用 | `requestId` |
| `GET /api/v1/child/mode` | 活跃儿童 | 读取未成年人模式与边界 | 不适用 |

共享Zod契约和Fastify JSON Schema同时校验请求与响应。无令牌返回`UNAUTHORIZED`，角色不符返回`FORBIDDEN`，停用儿童返回`ACCOUNT_DEACTIVATED`。相同`requestId`和相同载荷可安全重放；载荷变化返回`IDEMPOTENCY_CONFLICT`。

## 4. 数据结构

阶段2迁移创建10张InnoDB业务表：

1. `policy_versions`：同意或儿童说明版本与内容摘要；
2. `sites`：受控站点；
3. `pilot_invitations`：邀请摘要、批次、有效期和使用状态；
4. `guardian_accounts`：监护人化名和状态；
5. `enrollments`：邀请开通状态与幂等请求；
6. `child_accounts`：儿童化名、年龄段和强制未成年人模式；
7. `guardian_consents`：政策版本、授予与撤回时间；
8. `guardian_child_links`：监护人与儿童关系；
9. `access_sessions`：角色、主体、令牌摘要和停用状态；
10. `audit_entries`：动作、主体、目标、请求和时间。

禁止在这些表或共享契约中出现`real_name`、`phone`、`id_card`、`face`等身份字段。时间以UTC写入数据库。

## 5. 审计动作

本阶段必须产生并验证：

- `guardian_consent.granted`；
- `child_account.activated`；
- `guardian_consent.withdrawn`；
- `child_account.deactivated`。

审计元数据不得包含会话明文、邀请码明文或真实个人信息。

## 6. Web交互标准

- 一屏只保留一个主要行动；
- 监护同意、儿童说明和撤回确认均默认未勾选，未勾选时主要按钮不可用；
- 本地开发预填公开合成邀请码`XIAOBAN-DEMO-2026-02`并明确标注不可用于真实试点；
- 页面明确“当前阶段不会启动自由对话”；
- 监护状态展示同意版本、儿童化名、未成年人模式和普通聊天隐私边界；
- 撤回完成页明确说明停用立即生效；
- 375px手机视口不得横向溢出，按钮触达尺寸至少48px。

## 7. 本地人工验收账号

为避免一次性合成邀请码在浏览器关闭后妨碍重复验收，开发环境提供一个明确标注的“小树”合成测试账号：

- 正式邀请、同意、撤回和会话规则不变；测试账号不是正式登录方式，也没有密码或长期令牌；
- `pnpm db:seed:dev`幂等建立固定虚构站点、监护关系、同意和儿童账号，不包含真实个人信息；
- `POST /api/v1/dev/test-account/session`只在非生产回环API装配，默认`buildApp()`、生产环境和非回环监听均不注册；
- 每次请求由服务端生成新的随机儿童会话令牌，数据库只保存摘要，并在同一事务内撤销该合成账号之前的活跃儿童会话；
- Web入口只由Vite开发模式动态加载，令牌仍只放在`sessionStorage`；关闭后重新点击即可取得新会话，不把正式流程改为持久登录；
- 生产Web构建不得包含测试账号端点、版本、按钮或账号文案。
