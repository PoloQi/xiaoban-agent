# 开发工作流程

## 1. 小步原则

每次开发只完成一个可验证的小目标。

默认限制：

- 一个任务只跨一个主要模块；
- 一次最多包含3个紧密相关交付物；
- 不同时做新功能、架构重构和大范围视觉改版；
- 未达到当前轨道阶段退出门槛，不开始该轨道下一阶段；
- 发现更大问题时记录为待办，不顺手扩展范围。

## 2. 开发前

1. 阅读agent.md；
2. 阅读docs/00_INDEX.md；
3. 查看docs/07_EXECUTION_ROADMAP.md中的当前阶段；
4. 阅读当前产品PRD（AI陪伴智能体_PRD_V0.4_产品版.md）；
5. 查看最新开发日志的待办和阻塞；
6. 明确本次目标、非目标和验证方式；
7. 确认涉及的需求ID、数据和安全标准；
8. 检查现有未提交或不相关改动并保护用户工作。

任务描述格式：

- 目标：
- 范围：
- 非目标：
- 风险：
- 验证：
- 完成条件：

## 3. 实现中

- 先写最小失败用例或验收检查；
- 只修改与目标直接相关的文件；
- 优先复用现有契约和组件；
- 不提前设计未被当前需求使用的抽象；
- 不添加未批准的第三方服务；
- 不在代码、日志和截图中放秘密或真实儿童数据；
- 发现安全边界不清时停止实现并记录待确认；
- 连续工作超过60分钟时向用户提供简短进度。

## 4. 实现后

按风险从低到高验证：

1. 格式和静态检查；
2. 单元测试；
3. API或模块集成测试；
4. 核心用户流程；
5. 页面视觉和可访问性；
6. 安全与权限回归；
7. 故障、降级和回滚路径。

验证结果必须记录具体命令或检查项，不写“应该没问题”。

## 5. 开发日志

每次任务结束必须更新当天的开发日志。

日志目录：开发日志

日志至少包含：

- 本次目标；
- 已完成；
- 修改文件；
- 验证结果；
- 待办；
- 阻塞与风险；
- 下一步建议。

使用脚本：

powershell -ExecutionPolicy Bypass -File .\scripts\update-dev-log.ps1

自动任务每天复核一次日志，但自动任务不能代替任务结束时的即时记录。

## 6. 文档同步

以下变化必须在同一任务更新文档：

- 产品范围与验收；
- 技术栈、目录或接口；
- 数据字段、保留和权限；
- 风险等级、通知和SLA；
- 设计令牌和组件行为；
- 测试门槛、部署和回滚；
- 当前路线图阶段。

## 7. 评审

需要安全评审：

- AI输入输出；
- 风险分类与工单；
- 监护权限；
- 数据收集、导出和删除；
- 第三方模型、通知和分析服务；
- 语音、定位、摄像头、设备数据和长期记忆。

需要设计评审：

- 儿童新页面；
- 风险、同意和权限页面；
- 新导航和跨端切换；
- 重要文案变化。

## 8. 暂停条件

出现以下情况必须暂停并请求确认：

- 责任主体或数据用途不清；
- 需要在受控儿童试点范围内切换轨道或进入真实儿童试点；
- 需要真实儿童数据；
- 需要新外部服务或费用；
- 需要真实发送通知；
- 需求与安全标准冲突；
- 无法验证回滚；
- 现有用户改动与本任务冲突；
- 当前轨道阶段退出门槛未达到。

## 9. 任务交付格式

最终说明保持简短并包含：

- 结果；
- 关键变更；
- 验证；
- 未完成或风险；
- 下一步最小建议；
- 相关文件链接。
