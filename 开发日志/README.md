# 开发日志说明

## 1. 目的

本目录按日期记录项目开发事实，帮助团队知道：

- 今天完成了什么；
- 修改了哪些文件；
- 做了哪些验证；
- 还剩什么；
- 有哪些风险或阻塞；
- 下一次应从哪里继续。

日志不替代PRD、技术文档或版本控制。

## 2. 命名

每日文件使用：

YYYY-MM-DD.md

模板：

TEMPLATE.md

## 3. 记录时机

- 每次开发任务结束时即时记录；
- 每天由自动任务复核一次；
- 发布、回滚、安全事件和重大决策必须单独记录；
- 当天没有代码变更时，自动任务只记录“无开发变更”和当前待办，不编造完成事项。

## 4. 写作要求

- 只写已发生的事实；
- 完成项附文件或验证；
- 待办是下一步最小任务，不列大而空的愿望；
- 阻塞说明需要谁或什么条件；
- 不写密钥、账号、真实儿童信息和完整敏感对话；
- 不把计划写成已完成。

## 5. 手动更新

在项目根目录运行：

powershell -ExecutionPolicy Bypass -File .\scripts\update-dev-log.ps1

也可以传入内容：

powershell -ExecutionPolicy Bypass -File .\scripts\update-dev-log.ps1 -Summary "完成阶段0标准文件" -Completed "建立docs索引","建立安全标准" -Todo "确认技术栈决策"

## 6. 自动更新

Codex每日任务默认在北京时间21:30检查最近修改、当前路线图和当天日志，只更新日志，不自动推进业务开发。

自动任务与人工记录冲突时，以可验证的文件和测试结果为准。
